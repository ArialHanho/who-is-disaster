# Who is disaster

**바탕화면에서 함께 일하는 코드 검토 비서 · v0.3.1**

GitHub 저장소와 로컬 작업 폴더를 연결하면 브랜치·열린 PR·저장된 미커밋 변경을 함께 살펴봅니다. 오버엔지니어링, 순환 의존성, 변경 누락, 동시 작업의 충돌을 코드 근거와 함께 보여주고, 사용 중인 AI에 전달할 수정 지시문을 만듭니다.

## 할 수 있는 일

- GitHub 로그인 후 여러 저장소 선택, 전체 브랜치·열린 PR 자동 수집
- 소스 파일 수·총용량으로 잘라내지 않는 수집과 AI 분할 검토
- 격리된 가상 통합본에서 변경 충돌과 순환 의존성 확인
- 문제 코드·관련 호출부·수정 지시문, 수정 후 코드 기준 재확인
- 정상 변경·해결에는 조용히 기록하고, 같은 문제의 반복 알림 억제
- 캐릭터 이동·쓰다듬기·말풍선, 선택 가능한 가벼운 한마디와 날씨

저장소를 수정하거나 PR을 자동 작성하지 않습니다. AI는 기존 **Codex CLI의 ChatGPT 로그인**을 사용합니다. 별도 API 키로 자동 전환하지 않으며 구독 사용량·한도가 적용됩니다.

## 실행

### Windows 설치형

[Releases](https://github.com/ArialHanho/who-is-disaster/releases)에서 `WhoIsDisaster-Setup-0.3.1.exe`를 받아 설치합니다. 시작 메뉴의 **Who is disaster**를 실행하면 캐릭터만 나타납니다.

코드 분석에는 **Git 2.38 이상**, **Codex CLI**와 해당 PC의 로그인이 필요합니다.

```powershell
git --version
codex login
codex login status
```

### 소스에서 실행

Python 3.11 이상을 준비하고 다음 명령을 실행합니다. 개발·패키징 검사는 Windows와 Python 3.12에서 수행합니다.

```powershell
git clone https://github.com/ArialHanho/who-is-disaster.git
cd who-is-disaster
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m agent_app
```

`start.bat`을 실행하면 전용 가상환경을 준비하고 콘솔 없는 캐릭터로 실행할 수 있습니다. 자세한 내용은 [실행·설정 안내](docs/usage.md)를 참고하세요.

## 처음 사용하기

1. 캐릭터 우클릭 → **비서 열기** → **GitHub**에서 로그인하고 저장소를 선택합니다. 로컬 폴더도 연결할 수 있습니다.
2. 저장소 설정에서 기준 브랜치, 전체 브랜치, 열린 PR, 미커밋 포함 여부를 정합니다.
3. **지금 분석**을 누릅니다. 큰 저장소는 전체 소스를 여러 묶음으로 검토하므로 시간이 더 걸립니다.
4. 문제를 펼쳐 근거를 읽고 **AI 수정 지시문 복사**를 사용합니다.
5. 수정 후 **수정됐는지 확인**으로 현재 코드와 비교합니다. 코드상 해결과 실제 테스트 통과는 별개입니다.

## 내 캐릭터 만들기

기본 여우·고양이·로봇으로 바로 사용할 수 있습니다. 개인 사진이나 특정 인물의 캐릭터 팩은 저장소와 설치 파일에 포함하지 않습니다.

직접 만든 투명 GIF·WebP·PNG 애니메이션과 `character.json`을 준비한 뒤 **캐릭터 바꾸기 → 애니메이션 팩 가져오기**로 선택하세요. 이름·크기·움직임 줄이기도 바꿀 수 있습니다.

파일 구조와 예제, 스프라이트 시트 규격, 원본 얼굴·의상을 유지하는 방법은 **[캐릭터 제작 안내](docs/characters.md)**에 있습니다.

## 전체 분석의 의미

선택한 소스·설정·문서를 모두 수집하고, 관계를 먼저 검토한 뒤 아직 전달하지 않은 코드도 끝까지 분할해 AI에 전달합니다. 같은 경로와 내용이 여러 브랜치에 중복되면 재사용하고, 다른 내용은 각각 검토합니다. 최대 2묶음을 동시에 검토하며, 완료한 묶음은 로컬에 저장해 같은 입력으로 재시도할 때 재사용합니다. 코드·브랜치·규칙·모델이 바뀐 요청은 다시 검토합니다. 진행 상태에는 완료·재사용한 묶음 수가 표시됩니다.

`.git`, 가상환경, 외부 의존성, 빌드 결과, 바이너리와 민감 파일은 제외합니다. 이미 병합된 과거 브랜치의 문제를 현재 코드의 새 경고로 되살리지 않습니다. 수집 실패나 AI 실패가 있으면 전체 검토 완료로 표시하지 않습니다. 전체 소스를 읽었다고 모든 논리 오류를 찾아낸다는 뜻은 아닙니다. 자세한 범위는 [분석 구조](docs/architecture.md)에 있습니다.
